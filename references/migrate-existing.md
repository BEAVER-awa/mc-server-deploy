# 迁移已有服务端到新机器

## 顺序：先量容量，再动手

```bash
du -sh <源目录>
du -sb <源目录>          # 字节数，用于对账
find <源目录> -type f | wc -l
```

到目标机器上看磁盘：

```bash
df -h; lsblk -f
```

**根分区往往不够。** 数据盘（如 `/data/data1`）通常单独挂载且有几十 GB 空闲，服务端应当放数据盘，而不是 `/root` 或 `/opt`。放数据盘后要跟用户说清楚实际路径，别让他按 `/root/server` 去找。

## 传输：SFTP 多线程 + 断点续传

前提判断：

```bash
which rsync          # 目标机/源机是否都有
ssh -o BatchMode=yes -o ConnectTimeout=8 root@host "echo ok"   # 是否已配置公钥
```

很多云主机 sshd 里 `PubkeyAuthentication no`（甚至被安全策略锁死），此时：
- **不要去改 sshd_config**，会影响用户既有访问；
- 用 paramiko 走密码 + 多线程 SFTP。

实现要点（`scripts/` 里没有现成脚本，按这几条写）：

1. **线程数**：8–14 条。单条常被限在 1–2 MB/s；带宽充足时 14 条能到 9–10 MB/s。
2. **断点续传判据**：`远端 size == 本地 size` 视为已完成。
3. **0 字节文件陷阱**：`sftp.stat()` 失败时若把 rsize 当 0，而本地文件恰好也是 0 字节，就会被误判"已完成"而永远不上传。**必须显式区分「文件不存在」和「文件大小 0」**，不存在的空文件也要建出来。这个坑会造成"总字节数分毫不差，但文件数少几千"的假阳性。
4. **失败重试**：单文件 `EOFError` / 连接断掉是常态，重试 3–4 次即可；整轮跑完再跑第二遍补漏（成本极低，因为完成的都跳过了）。
5. **传输前先测速**：拿 50–200 MB 的文件试一条连接，估算总时长。**不要为了测速反复测多轮**——用户会等得不耐烦，边传边看更实际。

## 对账（必做，别只看日志说完成）

1. 逐文件比对：远端相对路径 + 大小，与本地清单求差集，统计 缺失/多余/大小不符。
2. 总字节数比对（对得上不代表没缺文件，见上面 0 字节陷阱）。
3. 抽查哈希：`server.jar`、`server.properties`、`world/level.dat`、几个大 `.mca`、几个 mod jar，本地与远端各算 md5 对比。

## 迁移后必查的「隐性依赖」

服务端文件夹之外的依赖，复制文件是带不过来的，**必须主动问自己三遍**：

- **数据库**：LuckPerms / Ledger / 经济 / 登录插件可能用 MySQL，数据在库里不在文件夹里。新机器没有库就会启动即崩（HikariPool 报错）。迁移时要问用户"要不要旧数据"，要就得在旧机 `mysqldump` 导出。
- **外部服务**：跨服代理（Velocity/BungeeCord）配置在代理机上；地图/皮肤服务、白名单系统。
- **启动脚本**：原机器的 `.bat`/`.sh` 里可能有 JVM 参数（内存、GC、Aikar 参数），复制过来后要改成新环境的内存值。
- **端口**：`server.properties` 的 `server-port`、插件的 web 端口（如统计面板），都要在新机的端口映射里体现。

## 收尾

- 停掉临时进程，删掉本地临时脚本（**含密码的脚本必须删**），删掉加到远端 `authorized_keys` 的临时公钥。
- 把传输日志、对账结果留在工作区，用户排查时能看。
